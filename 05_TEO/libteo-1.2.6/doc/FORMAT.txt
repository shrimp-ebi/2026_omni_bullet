######################################################################
0. TEO Image Format とは…

TEO フォーマットは、過去の画像フォーマット、ライブラリの反省から、
  1. プラットホームに一切依存しない
  2. 表示するための画像だけでなく、画像を扱う研究を行う人が使うことを
     前提に、様々な形式の画像データを扱うことのできるフォーマットとする
  3. 十分に拡張性のあるフォーマットにする。
ということを目的としたものです。

TEO の名前は、開発メンバーの所属である, Tsukuba, ETL, Okayama の頭文字
からとっています。

TEOファイルは、他のファイルフォーマットとの区別を容易にするため、サフィッ
クスを *.teoにすることを推奨します。ただし、これは強制ではありませんの
で、混乱のないように注意しながら自由に名前をつけることができます。

また、TEO フォーマットに基づくアクセスライブラリやビューアなどの周辺ツー
ルは、別途開発していくことになります。


######################################################################
1. TEO Image Format Version 1

TEO フォーマットは順にヘッダ部、データ部、フッタ部の３つのパートで構成
されます。ただし、フッタ部は省略することができます。

--------------------------
ヘッダ部(テキストデータ)
--------------------------
データ部(バイナリデータ)
--------------------------
フッタ部
--------------------------

1.1. ヘッダ部

ヘッダ部は次のように定義します。
-----
マジックナンバー<D>バージョンナンバー[<D>#コメント]<CR>
[#コメント<CR>[#コメント<CR> ...]]
横サイズ<D>縦サイズ[<D>オフセットx<D>オフセットy][<D>#コメント]<CR>
[#コメント<CR>[#コメント<CR> ...]]
画素値の型<D>画素値のビット数[<D>#コメント]<CR>
[#コメント<CR>[#コメント<CR> ...]]
プレーン数<D>フレーム数[<D>#コメント]<CR>
-----

※<D>:	デリミタ、1個以上のスペース(0x20)もしくはタブ(0x09)
※<CR>:	改行(0x0a)



例：5×5のカラー画像
-----
TEO 0 # This is TEO sample.
5 5
# pixel type is unsigned integer.
# pixel size is 8bit.
U 8
# 3 planes [reb green blue], 1 frame.
3 1
(Un~jwtC#93m]7&gV@=$9fJK9
-----

1.1.1. マジックナンバー、バージョンナンバー

マジックナンバーは、0x54 0x45 0x4f の 3byte のデータ。

※それぞれアスキーコードで 'T', 'E', 'O' にあたります。

バージョンナンバーは、TEO のバージョンを表す数字で、現時点では '0'と'1'
のいずれかが考えられますが、特に理由のない限り '1' を入れます。


1.1.2. 縦サイズ、横サイズ
縦サイズ、横サイズは画像のサイズで自然数。


1.1.3. オフセット (Version 1 以降)
画像の左上の座標を整数値で与える。省略時は 0 0 と解釈されます。

version 1 以降のフォーマットでは、画像のオフセットを与えることができま
す。オフセットは省略可能なため、version 0 に対して上位互換性があります。


1.1.4. 画素値の型、画素値のビット数
画素値の型は U/S/F のいずれかの文字で、それぞれ
U:	Unsigned(符合なし整数)
S:	Signed(符合あり整数)
F:	Float(浮動小数点数)
を表します。

また画素値のビット数は、各画素のデータ長をビット数で表します。ただし、
ビット数は 1/8/16/32/64 のいずれかとなります。

例えば、
S 8
ならば、8bit の符合つき整数を表し、
F 64
ならば、64bit の浮動小数点数を表します。

ビット数が 1 の場合は特別で、型に関係なく２値データを表します。


1.1.5. プレーン数、フレーム数
それぞれ、自然数で表します。

TEO はマルチプレーン・マルチフレームをサポートしますが、それぞれのプレー
ン、フレームが何を表すかについては特に定義しません。

また、各プレーン、フレームの画像サイズ、画素値の型、ビット数は同じもの
でなければなりません。


1.1.6. コメント
テキストデータ。

TEO では、ヘッダ部にコメントを含むことを許しますが、各種ツール、ライブ
ラリでは基本的にこれを無視する。

コメントとして扱うのは以下の二通り。
 1) 行頭が # で始まる行。ただし、ヘッダの最初の行と、最後の行にはコメ
    ントを入れてはいけません。
 2) 行末の # 以降。ただし他のヘッダと # の間には必ず <D>(デリミタ) を
    入れます。

なお、行頭が「#%」で始まるコメント行は特殊な意味を持ち、ユーザ拡張とし
て使うことができます。


1.2. データ部

データ部には、各画素値をバイナリデータとして入れます。
データは、ヘッダー部のフレーム数のあと、改行(0x0a)の次から始まります。

データ部の大きさは、ヘッダから計算でき、
-----
横サイズ × 縦サイズ × (ビット数/8) × プレーン数 × フレーム数 [byte]
-----
となります。

※ビット数が 1 の場合については例外で、1.2.3 で述べます。


1.2.1. プレーンとフレームの取り扱いについて

前にも述べたように、 TEO では各プレーン・フレームが何を表すかについて
は特に定義しません。

ただし、RGB カラー画像のように各画素をベクトルで表現する場合は各プレー
ンでベクトルの各要素を表し、動画を扱う場合は各フレームで時刻の違う画像
を表すことを推奨する。

※ステレオ画像のように、異なるカメラで同時に撮影した画像については未定.

※汎用ビューワでは、特に指定がない場合、3プレーンなら RGB カラー画像、
複数フレームなら動画として解釈することを推奨する。

また、データを収める順序がプレーンとフレームで異なります。プレーンにつ
いては同じ座標のデータを連続して書き、フレームについては1フレーム目の
データを全て書き終ってから2フレーム目のデータという順序になります。


1.2.2. 複数バイトのデータの取り扱いについて

画素値のビット数が 16/24/32/64 のとき、つまり複数バイトのデータをファ
イルに書く場合、上位バイトから書き込む方法と下位バイトから書き込む方法
がありますが、TEO では必ず上位バイトからファイルに書き込みます。


1.2.3. 1bit データの取り扱いについて

画素値のビット数が 1 の場合、各画素を上位ビットから順につめて8画素で 1
バイトとして扱います。

複数プレーンの場合は、プレーン毎に8画素ずつまとめて並べます。

横サイズが 8 の倍数でない場合は、半端なビットを無視して扱います。

例えば、横サイズが 9 の1プレーンの画像の場合
-----
 1byte 目    2byte 目
| 10110101 | 0******* |
* の部分は無視
-----
のように扱います。

1bit の場合のデータ部の大きさは
-----
([(横サイズ-1)/8] + 1) × 縦サイズ × プレーン数 × フレーム数 [byte]
・ただし [x] は floor 関数。
-----
となります

1.3. フッタ部

フッタ部には、基本的にどんなデータを書いても自由ですが、汎用ツールはこ
の領域を無視します。

※ただし TEO から TEO へ変換するコンバータでは、この領域を保存するか
どうかは保証しない。


######################################################################
2. Compressed image

TEOファイルを gzipによって圧縮したファイルも、TEOファイルと見なします。
TEOファイルはマジックナンバーによって判別されますので、サフィックスは
*.teo.gzになっている必要はありません。むしろ、圧縮／非圧縮のいずれの形
式も、*.teoとすることを推奨します。

なお、２重圧縮などの混乱を防ぐため、TEOファイルの圧縮・伸長はそれぞれ
コマンド teogzip / teoungzip を使うようにして下さい。
